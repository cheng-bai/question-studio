# 题包协议 v0.1

题包是 AI 和编辑器共用的交付格式。AI 可以先整理题干、答案、解析与建议考点，再按本规范交付；编辑器以单题为单位导入，并按讲义清单组合顺序。该协议不依赖某一家模型，不包含自动调用模型、执行脚本或远程请求的能力。

## 文件与清单

本版使用一个 UTF-8 `*.题包.json` 文件，内含虚拟文件表。独立 Markdown 文件打包在 JSON 字符串中，配图打包为 base64 data URI，因此单个文件可完整迁移。未来可以增加同内容的目录/ZIP 适配，本版暂未实现。

```json
{
  "format": "question-studio-package",
  "schema_version": "0.1",
  "package_id": "functions-intro",
  "title": "函数基础",
  "questions": [
    {
      "question_id": "function-001",
      "revision": 1,
      "file": "questions/function-001.md",
      "sha256": "单题Markdown原始UTF-8内容的64位小写SHA-256"
    }
  ],
  "files": {
    "questions/function-001.md": "完整单题Markdown字符串"
  },
  "handout": {
    "title": "函数基础讲义",
    "subtitle": "复习课",
    "items": [
      {
        "question_id": "function-001",
        "question_revision": 1,
        "role": "例题",
        "reason": "引出代入计算"
      }
    ]
  }
}
```

上面的哈希占位符必须换为真实哈希。可以直接使用 [完整合成题包](../examples/ai-package-demo.题包.json)，其中包含 3 道题、配图和 `3 → 1 → 2` 的讲义顺序。示例不包含真实试卷；配图为本项目绘制的合成二次函数图像。

`package_id`、`question_id` 使用 1–128 个 ASCII 字母、数字、下划线或短横线，首字符必须为字母或数字；UUID 可以使用。题目 `revision` 是正整数。一个题包最多 200 道题，同一 `question_id` 只能出现一次；讲义可以重复引用同一题。讲义的版本引用必须与包中题目版本完全相同。

`handout` 可省略。存在时，`title`、`subtitle`、`items` 必填；单项中的 `role`、`reason` 可省略，导入时视为空字符串。本版不含章节/分组结构。

## 单题 Markdown

```markdown
---
schema_version: "0.1"
question_id: function-001
revision: 1
type: 填空题
tags:
  - 函数求值
tag_origin: suggested
source:
  title: 合成演示
  file: demo.md
  original_number: "1"
  line: 1
---

## 题干

已知 $f(x)=2x+1$，则 $f(2)=$ ______。

## 答案

$5$

## 解析

代入 $x=2$，得到 $2\times 2+1=5$。

## 教学备注

先检查是否理解函数求值。
```

frontmatter 中列出的字段全部必填，不接收未知字段。`type` 仅允许 `填空题`、`选择题`、`解答题`。`tags` 是字符串数组，可以为空；`tag_origin` 仅允许 `suggested`（建议，待教师确认）、`source`（原材料已有）、`manual`（人工确认）。`source.title`、`source.file`、`source.original_number` 为非空字符串，`source.line` 为正整数。来源用于追溯，不能代替数学正确性复核；共享题包前请检查来源字段中是否有私人信息。

正文必须有非空 `## 题干`，其余三个字段可省略。按 Markdown 标准识别标题前的 0–3 个空格，缩进的答案等字段同样独立切分。字段标题不得重复，不允许未知二级标题、一级标题或第一个字段前的正文；这些情况直接报错，避免将内容静默丢失。正文中的三级及更深标题、普通 Markdown、公式、引用与列表会保留。代码围栏与 `$$ ... $$`、`\[ ... \]` 块公式内的字段标题不参与切分；支持独占行开头的 `\begin{equation}`、`align`、`gather`、`multline`（含带星号形式）及 `displaymath` 环境，必须使用对应 `\end{...}`。代码围栏和块公式必须闭合，混用结束分隔符会报错。YAML 重复键及 alias 禁止使用。

## 图片

`files` 中图片路径必须位于 `assets/`，扩展名可为 PNG、JPEG/JPG、WebP、GIF；值必须为对应类型的 base64 data URI。不接受 SVG、脚本或外部图片 URL。包中文件合计最多 50 MB，文件数量最多 2200。CLI 另要求 JSON 文件本身不超过 50 MB。

正文中的图片引用统一按**包根路径**书写，例如 `![题图](assets/example.png)`；编辑器适配时将其映射到本地工作区。不要写 `../assets/example.png`。全部文件路径与图片引用禁止绝对路径、协议、`..`、`.`、反斜杠和查询参数；编码后的遍历也会拒绝。题干、答案、解析、教学备注中的图片都必须随包提供。没有被引用的图片及清单之外的 Markdown 会被拒绝。

编辑器导出使用 Markdown 图片语法寻找本地配图，再以图片 data URI 的 SHA-256 形成 `assets/<hash>.<ext>`，改写四个正文字段中的图片地址。引用形式和行内形式均支持；仅改写真实图片目标及被图片使用的引用定义，普通文字、代码和公式中的相同字符串保持原样。缺图或网络图片会使导出失败，不生成缺图题包。百分号编码与中文/空格路径统一解码为资源键，重复规范路径会报错。

## 校验与 AI 交付约定

结构定义在 [`schemas/question-package.schema.json`](../schemas/question-package.schema.json)，语义校验与导出在 [`src/question-package.js`](../src/question-package.js)。网页与命令行使用同一校验器。

共享 JavaScript API 为 `await validateQuestionPackage(value)` 与 `await makeQuestionPackage({ title, questions, assets, handout? })`。后者接收现有题库题目记录，优先保留 `q.protocol.questionId/revision`，否则使用 `q.id` 与版本 1；重复题目身份在写入任何虚拟文件前报错；`handout` 使用上面的协议字段名。前者返回规范化结果：`{ packageId, title, questions, assets, handout, warnings }`；单题字段为 `questionId/revision/file/type/stem/answer/analysis/notes/tags/tagOrigin/source`，来源字段为 `title/file/originalNumber/line`；讲义项为 `questionId/revision/role/reason`。`rewriteImageDestinations(text, replacements)` 使用 `Map<原图片URL, 新URL>` 仅改写实际图片目标，`questionImageReferences(text)` 返回排除代码和公式后的真实图片引用。校验失败抛出带位置的 `Error`，调用方应保持原工作区不变。

```sh
node scripts/validate-package.mjs examples/ai-package-demo.题包.json
```

命令只读文件，不写题库，也不访问网络。失败返回退出码 1，并给出字段或文件位置。SHA-256 按**原始 Markdown 字符串的 UTF-8 字节**计算，不能在计算后改换行或内容。

校验覆盖 Schema、单题身份与版本、哈希、切分边界、图片完整性和讲义引用。它不证明答案、解法、考点或来源内容正确。AI 不得附加 `ai_verified`、`checks_passed` 等自我认证字段；建议考点仍以待确认状态呈现。学生版继续隐藏答案、解析、考点与教师备注。

可将以下要求交给任意 AI：

> 按题序题包协议 v0.1 整理材料。保留完整题干、原题号、来源与配图；把题干、答案、解析、教学备注放在明确字段中。无法确认的答案和考点不要编造；考点未获人工确认时使用 suggested。每题使用稳定 question_id 和正整数 revision，生成准确 SHA-256。讲义清单只引用包中确定版本。交付后运行同一校验器；校验通过仅表示结构与引用完整。

## 现阶段边界

题包内身份与版本锁定属于本次协议能力；跨题包的冲突、导入工作区的去重和副本策略由工作区适配层处理。此协议不承诺独立题库服务、数据库归档、跨设备同步、AI 数学审校、题目自动升级或批量 ChangeSet。后续版本必须显式升级 `schema_version` 并提供兼容策略。
