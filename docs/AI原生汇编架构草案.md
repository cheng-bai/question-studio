# 题序：AI 原生题目资产与汇编架构

状态：架构讨论稿 v0.2，2026-10-13。标准题包 v0.1、只读校验 CLI、AI 任务模板与工作区回导已在网站 0.4.0 实现，确切格式见《题包协议-v0.1》。本文其余版本事实源、文件题库、ChangeSet、操作 CLI/MCP 与多讲义方案仍为拟议架构；已有能力以项目根目录 `PROJECT_STATE.md` 为准。

## 产品目标

让 AI 润色后的 Markdown 成为可复用教学资产：导入并切分成独立题目，经教师核对后归档；AI 或教师选题、分组、排序、编辑，再生成可复现的学生版和教师版讲义。PDF 是讲义的一个输出，一道题可以服务于多份讲义和多轮教学。

完整流程：

```text
原始 PDF / 题图 + 转录、润色后的 Markdown
  → 导入草稿与配图检查
  → 题目边界、答案、解析、来源、考点核对
  → 版本化题目库
  → 汇编任务 → AI 提交编排草案
  → 教师拖拽、编辑、确认
  → 讲义版本 → 学生版 / 教师版 / PDF / 课堂互动 HTML
```

## 核心对象及职责

| 对象 | 保存的事实 | 主要作用 |
| --- | --- | --- |
| Source | 来源标识、原文件路径、文件哈希、原题号/页码或行号、原始材料 | 回源和校对；保留已有来源信息，不虚构出处 |
| Question | 稳定 ID、题目版本、题干、答案、解析、类型、考点、配图引用、派生关系 | 一题一个长期资产；题号只是展示顺序 |
| Handout | 稳定 ID、标题、章节、有序题目引用、锁定的题目版本、局部修改、打印设置 | 表达某一份讲义；可复制、保存多个版本 |
| CompilationTask | 教学目标、检索范围、题数、顺序/梯度、允许修改范围、必要约束 | 把“帮我编一份讲义”变成有边界的任务 |
| ChangeSet | 基础版本、拟新增/修改/排序操作、依据和检查结果 | 让 AI 的变更可预览、可拒绝、可应用、可撤销 |

题目保存小问结构，但首版大题仍是拖拽与归档单位。章节说明、练习提示和已有交互模板可以作为讲义中的其他块类型，题号只对题目块连续编号。

## 数据原则

1. **题目 ID 与题号分开。** 改顺序不换 ID；重复导入已有 ID 走版本检查；无 ID 的历史 MD 由导入器建立 ID，并对内容相似项给出重复候选。内容哈希用于检查与候选检索，不单独决定两份材料是否同源。
2. **题目版本和讲义版本分开。** 每份讲义锁定所用题目版本，题库后续更新不悄悄改变旧讲义。打印设置属于讲义，不写进题干。
3. **编辑副本延续现有行为。** 讲义中的局部改动保存为局部版本/覆盖；用户选择“另存为题库新题”才生成新 ID，并记录 derivedFrom。纠正同一原题的错字或答案可形成题目新版本，需明确操作，不能自动替换所有既有讲义。
4. **原文、来源、AI 建议与核验分开。** 保留原文与配图。标签记录来源、建议者和确认情况；转录核对、答案复核、考点确认是不同检查，不用一个“已审核”布尔值代表全部正确。
5. **不确定内容可表达。** 缺失解析、缺图、存疑题干均有明确状态；AI 不为通过格式校验编造答案或来源。学生版按字段排除答案、解析、考点和教师备注，题干混写答案仍需内容核对。
6. **历史版本可实际取回。** 已发布题目版本和配图不能原地覆盖；配图使用内容哈希或版本路径引用。锁定版本需要保留正文、图片及元信息，不能只保存一个版本号。

## 面向不同 AI 的开放协议

核心是模型无关的数据与操作契约。任何能够生成文件或调用工具的 AI 都可以尝试遵守；是否合格由程序校验，不能依赖模型承诺。

### 已实现的两条导入路径

- **历史 MD 路径**：保留自动/数字加点拆题与人工预览，不要求重写原有资料。
- **AI 标准题包 v0.1**：单个 `*.题包.json` 内保存虚拟 Markdown 文件与配图、题目身份/版本、SHA-256 和可选讲义题序。网页与只读 CLI 使用同一校验器。具体字段、合成示例及限制见 [题包协议-v0.1](题包协议-v0.1.md)。

当前可通过任务模板导出完整候选题与规范，交给任意 AI，回导结构校验后由教师应用。题库导入拒绝同题同版本内容冲突，复用相同原题，保留不同版本；讲义独立副本不修改题库。建议题序可追加，角色/依据放入教师备注。数学建议未被网站自动核验。

后续可增加与 JSON 虚拟文件表对应的目录/ZIP 适配、文件题库、章节结构与局部覆盖。以下是未来目录方案，不是当前可直接读取的文件夹协议：

```text
ai-package/
  manifest.json
  questions/q-demo-001.md
  assets/diagram-001.png
  handouts/h-demo-001.json
```

每次协议扩展需配套 Schema、字段语义、正反例、迁移说明和校验器。不同层的题目身份和版本冲突必须报错，不能猜测覆盖。

### 可调用操作与检查回执

网页和 AI 共用同一操作层，避免一套网页逻辑和另一套 AI 写库逻辑逐渐不一致。当前已有只读题包校验 CLI；后续实现本地题库操作 CLI，再按需要提供 HTTP / MCP 适配。

拟议操作：

| 操作 | 输入/约束 | 输出 |
| --- | --- | --- |
| import / validate | 标准包或历史 MD；默认先预演 | 题目边界、缺图、格式、重复候选、警告与错误位置 |
| search / get | 查询条件、题目 ID、版本 | 完整题干与可追溯来源；不只返回摘要 |
| proposeCompilation | 教学目标、题库范围、题数、分组约束 | 按已存在 ID 组成的编排草案及选题依据 |
| proposeChange | 基础版本、操作清单、请求 ID | 可见差异、冲突信息及待应用的变更集 |
| applyChange | 用户确认/既有授权、基础版本仍匹配 | 新版本与回执；过期版本拒绝静默覆盖 |
| export | 讲义 ID/版本、学生/教师、打印参数 | 导出文件、引用清单和检查结果 |

写入操作应带请求 ID，重复提交不会重复建题；缺图或格式错误返回结构化位置，AI 可以修正后再交付。第一次提交只生成草案，明确的自动化任务可按用户事先授权应用；确认方式不与某家模型绑定。

多题或讲义的批量变更应明确原子提交范围：逐实体检查基础版本，准备并校验所有新文件，成功后统一发布提交清单。失败时保持旧清单可用、回收未发布的暂存文件，不能把一半完成的汇编标为成功。实际实现需覆盖并发、崩溃恢复和回滚测试；搜索索引在提交后更新，异常时从已发布文件重建。AI 交付包经操作层应用，不直接改写已发布文件。

MCP 与各 AI 的 Skill 只是调用或解释协议的适配层。权威规范与校验器留在项目仓库，避免每个 AI 维护一份不同标准。

## 适合当前规模的实现结构

```text
React 编辑器        AI 文件交付 / CLI / 后续 MCP
      \              /
       共用领域操作层
         /        \
    导入与校验    题目、讲义、变更版本
         \        /
       本地持久化与搜索适配
         /        \
   Markdown + 资源文件    可重建 SQLite 索引
```

- 继续使用现有 React、KaTeX 和拖拽模块，逐步把领域操作从 `App.jsx` 提取出来。
- 题目正文以版本化 Markdown 作为事实源；讲义/清单 JSON 保存结构。SQLite 保存可重建索引，不成为一份需要同时手改的正文副本。
- 本地服务负责原子写入、基础版本检查、路径与图片校验；索引落后时可以重建。私有材料保存在用户选定目录，不进入源码仓库。
- IndexedDB 保留为浏览器工作缓存，已有 `.题序.json` 提供迁移入口。先建立备份与迁移预演，再切换持久化；仍可保留纯浏览器试用模式。
- 固定渲染依赖、字体和纸张设置，让同一内容在固定环境下可重现。打印成功、公式渲染通过、数学复核分别报告。
- 已有交互模板通过注册 ID 和参数引用；普通交付包不携带任意可执行 JavaScript。

## 跨对话持续开发

代码现已整理到独立 Git 项目，作为持续开发入口；原型副本与私有资料不纳入公开仓库。后续在此项目开展持久化升级，已完成的开源整理不代表下述数据协议已实现。

拟议的项目入口：

```text
README.md                     # 启动、使用和验证方法
PROJECT_STATE.md              # 当前事实、约定、缺口、下一步与验证日期
docs/AI原生汇编架构草案.md     # 目标与演进方案；接受后保留版本记录
docs/decisions/               # 重要设计决定、理由、适用范围
schemas/                      # 实际实现的协议版本
examples/                     # 正确和错误的输入包
tests/                        # 格式、迁移、编排、渲染验收
AGENTS.md                     # 已建立的项目开发约定
```

新对话先读项目状态、相关设计决定和实际源码，再进行改动。每次开发结束记录变更、实际验证、未完成项、迁移影响及对应 Git 提交。架构草案与待办不代表功能完成；验收数字带日期。运行时资料、缓存、密钥和私有题库不提交到代码仓库。

## 建议实施顺序与完成标准

1. **协议小样（已实现首版）**：3 道含配图、答案解析的合成题包、Schema、共享校验器、CLI 与网页预览导入。后续用用户自选真实材料验收，不能把合成夹具通过当作任意资料都可无误导入。
2. **独立归档与多讲义**：固定 ID、题目版本、另存为新题、多个讲义、本地文件保存和旧工程迁移。完成标准：关闭浏览器后题目资产仍可读，题库更新不改变旧讲义，备份可恢复。
3. **AI 汇编操作**：任务说明 → 检索现有题 → 提交选题和编排草案 → 教师调整 → 保存讲义版本。完成标准：无效 ID、过期版本、重复提交均有正确结果；每题保留来源。
4. **连接更多 AI**：为共用操作层增加 MCP 或其他工具接口，按需要接入远程模型。完成标准：至少两种交付方式使用同一规范和校验器，私有资料的传出范围明确。

下一次最有价值的小闭环是第 1 步。无需同时重做网页、全库索引、持久化和 AI 接入。
